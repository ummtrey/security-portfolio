# Sensitive Data Exposure via Server-Rendered State > **Status:** Resolved (sanitized for portfolio) > **Severity:** Medium > **Class:** Information Disclosure > **Date:** 2026 > All target names, hostnames, and identifiers have been redacted. Published > as a methodology example, not to disclose a specific program's details. ## Summary A server-side-rendered page embedded its hydration state in the HTML. That state object carried more data than the rendered UI displayed - including internal fields and inventory/stock values not meant to be exposed to unauthenticated users. ## Impact Any unauthenticated visitor could read fields the application intended to keep server-side by inspecting the page source rather than the rendered page. The exposed values revealed internal business data (stock levels and non-public attributes) without any authentication or API call. ## Steps to Reproduce 1. Load the product page as an unauthenticated user. 2. View page source and locate the inlined hydration state (the framework's embedded JSON blob). 3. Observe fields present in the JSON that are absent from the rendered page. ```html ``` ## Root Cause The page serialized the full server-side data object into the client payload instead of projecting only the fields the UI needed. This is a common pattern with SSR frameworks that hydrate from an embedded state object. ## Remediation Serialize only the fields the client actually renders. Strip internal and sensitive attributes from the hydration payload on the server side. ## Lessons `__NEXT_DATA__` and equivalent hydration blobs are always worth reading in full - the UI showing a field and the response containing a field are two different things.
